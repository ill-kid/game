# 飞行棋网页小游戏设计

## 目标

把现有的飞行棋 HTML 原型升级为可在手机、iPad 和电脑上使用的纯前端双人小游戏。两位玩家在同一台设备上轮流操作，不引入联网、账号、房间、服务器或外部依赖。

成品保留现有九个版本、棋子移动、特殊格、事件提示、进度保存和最小化能力，同时把聊天弹窗式原型改为独立游戏页面。体验融合轻松情侣桌游风与成人挑战卡牌风：轻松模式默认亲和、克制；成人模式通过设置开启，并允许使用更直接的事件内容。

## 范围

### 包含

- 九个现有版本的数据与规则。
- 同设备双人轮流掷骰、移动和触发事件。
- 手机、iPad、电脑的响应式布局。
- 轻松模式 / 成人模式切换。
- 成人模式的可选回合交接遮罩。
- `localStorage` 自动保存、手动保存、继续游戏和恢复默认。
- 玩家名称、棋子颜色、主题色、事件文本和规则开关自定义。
- 事件只在棋子最终停下时触发，继续遵循现有规则。
- 保留并整理最小化浮窗能力。

### 不包含

- 网络联机或实时同步。
- 账号、登录、云端存档。
- 付费、广告、排行榜。
- 新增后端服务或构建系统。
- 第一版的复杂动画编辑器或自定义棋盘路径编辑器。

## 用户流程

1. 用户打开开始页，选择版本。
2. 用户选择轻松模式或成人模式，填写两位玩家名称。
3. 用户可进入设置，修改颜色、事件和规则开关。
4. 用户开始游戏，看到棋盘、双方位置、当前回合和操作区。
5. 当前玩家掷骰，棋子移动到最终位置。
6. 只有最终停留的格子触发事件；后退或跳转完成后，以最终位置为准继续处理。
7. 事件卡展示接受方、格子文本和剩余回合信息。
8. 用户确认事件后进入下一回合；成人模式且开启遮罩时，先显示交接提示。
9. 刷新或重新打开页面时，可以继续最近一次进度。
10. 达到终点后展示结算状态，并允许重新开始或保留当前记录。

## 页面与模块

### 页面

- `index.html`：开始页、版本选择、棋盘预览、继续游戏入口。
- `game.html`：正式游戏页，负责棋盘、掷骰、移动结果、事件卡和回合交接。
- `settings.html`：模式、玩家、主题、事件和规则配置。

如果第一阶段为了保持现有预览兼容而继续使用 `flight-chess-popup.html`，它可以作为游戏页的过渡文件，但最终职责应与正式游戏页一致。

### 逻辑模块

- `game-data.js`：九个版本的原始格子与事件数据、默认主题和版本元数据。
- `game-engine.js`：掷骰、移动、后退、跳转、接受方判断、回合推进和终点判断。
- `storage.js`：统一处理存档版本、读取、写入、迁移和恢复默认设置。
- `ui.js` 或页面内 UI 控制层：渲染棋盘、事件卡、回合状态和 toast，避免规则逻辑散落在 DOM 事件中。
- `float-window.js`：保留拖动与恢复能力，改为显示当前游戏状态。
- `styles.css`：共享响应式布局、颜色变量、控件状态和模式主题。

## 游戏状态

状态结构保持简单、可序列化：

```js
{
  versionKey: 'foreplay',
  mode: 'light',
  players: [
    { id: 'player', name: '你', color: '#C4787A', position: 0 },
    { id: 'ai', name: '小机', color: '#7A9E8E', position: 0 }
  ],
  turn: 'player',
  lastDice: null,
  lastEvent: null,
  status: 'playing',
  settings: {
    handoffOverlay: false,
    allowBackSteps: true,
    allowJumps: true,
    allowPenaltyCells: true
  },
  customEvents: {},
  updatedAt: 0
}
```

规则引擎返回结构化结果，页面只负责展示：

```js
{
  dice: 4,
  startPosition: 8,
  landedPosition: 12,
  finalPosition: 10,
  lander: 'player',
  receiver: 'player',
  cellText: '后进2格',
  eventText: '...',
  roundsLeft: 2,
  status: 'playing'
}
```

## 规则兼容

- 只有停留在格子后才触发事件，路过格子不触发。
- “后进 X 格”实际减少位置；“退回到 N 格”跳转到指定格。
- 女仆版 / SM 版默认由女方接受；男仆版默认由男方接受；其他版本由停留者接受。
- “互相 / 一起 / 双方”按事件原文作为共同事件展示，不拆成两次惩罚。
- 双人同设备模式中，将原先的“机回合”命名为第二位玩家回合，避免误导；兼容现有 API 时保留旧字段映射。

## 响应式 UI

### 手机竖屏

- 顶部显示版本、模式和返回入口。
- 棋盘单列展示，可上下滚动。
- 底部固定当前回合、骰子和主要按钮。
- 事件卡以底部抽屉或居中弹层显示，确保按钮不被键盘或安全区域遮挡。

### iPad

- 竖屏采用手机布局的放大版。
- 横屏使用棋盘与事件面板并排，控制区固定在事件面板下方。
- 充分使用安全区内边距，避免刘海和系统手势区域遮挡。

### 电脑

- 使用居中的游戏桌面布局：左侧棋盘，右侧状态、事件和控制。
- 设置和版本选择使用侧栏或抽屉，保持棋盘连续可见。
- 支持鼠标、键盘焦点和 Enter / Space 操作。

### 视觉方向

- 轻松模式：暖白、浅木色、柔和红绿棋子，圆角控制在较克制的范围内。
- 成人模式：保留同一布局，增加深色背景、酒红或暗金强调色和更清晰的事件卡层级，不使用过度装饰或影响阅读的渐变。
- 事件卡是主要内容载体，保证长文本换行、按钮不被挤压、移动端可读。
- 图标按钮使用现有图标库或简单文本符号，仅用于明确动作；每个不熟悉的图标提供无障碍标签或 tooltip。

## 隐私与回合交接

回合交接遮罩是一个可配置的全屏或游戏区域遮罩。默认规则：轻松模式关闭，成人模式开启。用户可在设置中覆盖默认值。

遮罩只显示“请交给下一位玩家”和继续按钮，不显示事件文本、位置细节或上一位玩家名称以外的敏感信息。点击继续后才显示下一回合内容。页面失焦、切换标签页或浏览器恢复时不自动泄露事件内容。

## 自定义与存档

- 自定义事件按版本保存，默认数据不可被直接破坏。
- 编辑事件时保留恢复默认入口。
- 所有存档增加 `schemaVersion`，为未来字段变化保留迁移入口。
- 旧键 `flight_chess_progress` 和 `flight_chess_player` 继续读取，并迁移到统一存档格式。
- 存档写入失败时显示非阻塞提示，不影响当前游戏继续进行。

## 错误处理

- 找不到版本数据时回退到默认版本。
- 存档 JSON 损坏时忽略损坏记录，使用默认初始状态并提示用户。
- 掷骰过程中禁用重复操作，防止快速点击造成多次移动。
- 事件数据为空时显示安全的“本格无事件”提示，并正常推进回合。
- 屏幕尺寸改变时只重新渲染布局，不重置游戏状态。

## 测试与验收

### 逻辑测试

- 掷骰在 1 到 6 之间，重复点击不会产生双重回合。
- 后退格和指定跳转格会得到正确最终位置。
- 不同版本的事件接受方符合现有规则。
- 共同事件不会被拆成单人事件。
- 回合、胜负和存档恢复正确。
- 自定义事件只影响对应版本，恢复默认后回到原始数据。

### 手动验收

- 375px 宽手机竖屏：棋盘、按钮、事件长文本无横向溢出。
- iPad 横屏和竖屏：布局切换正常，操作区无遮挡。
- 1366px 以上桌面：棋盘与事件面板比例稳定，内容不漂移。
- 成人模式开启遮罩后，事件在交接前不可见。
- 刷新页面、关闭再打开页面后，进度和设置可恢复。
- 所有现有版本可以开始一局并完成一次掷骰流程。

## 实施顺序

1. 抽取现有数据与规则，建立统一状态模型。
2. 建立共享样式和三端布局骨架。
3. 实现正式游戏页和规则引擎。
4. 接入存档迁移与继续游戏。
5. 实现设置页、自定义事件和恢复默认。
6. 接入回合交接遮罩与最小化浮窗。
7. 按手机、iPad、电脑视口逐项验收，修复溢出和交互问题。

## 明确决策

- 只做同设备双人，不做联网接口。
- 默认轻松模式；成人模式由用户主动开启。
- 成人模式默认开启回合交接遮罩，但可在设置中关闭。
- 第一版沿用现有九种版本和事件文本，不主动扩写更露骨的新内容。
- 先保持纯 HTML / CSS / JavaScript，避免构建工具和部署复杂度。
